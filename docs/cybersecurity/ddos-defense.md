# DDoS: เข้าใจและป้องกัน

## DDoS คืออะไร
Distributed Denial of Service คือการทำให้บริการออนไลน์ไม่พร้อมใช้งาน โดยมีทราฟฟิกหรือคำขอจำนวนมากจากหลายแหล่งเข้ามาพร้อมกัน จนทรัพยากรของระบบรับไม่ไหว

## ประเภทในระดับแนวคิด
- **Volumetric:** ปริมาณทราฟฟิกสูงจนแบนด์วิดท์ไม่พอ
- **Protocol:** ใช้ข้อจำกัดของการสื่อสารเครือข่ายจนทรัพยากรส่วนหนึ่งทำงานหนัก
- **Application layer:** คำขอที่ดูคล้ายการใช้งานเว็บทั่วไป แต่สร้างภาระกับแอปพลิเคชัน

คำอธิบายนี้มีไว้แยกประเภทความเสี่ยง ไม่ใช่ขั้นตอนสร้างหรือส่งการโจมตี

## อาการที่อาจพบ
- latency สูงหรือ timeout
- ผู้ใช้จริงเข้าเว็บไม่ได้
- ปริมาณ request หรือ traffic เปลี่ยนไปผิดปกติ
- CPU, memory หรือ connection ถูกใช้งานสูง
- ระบบแจ้งเตือนจาก CDN, WAF หรือผู้ให้บริการ

อาการเหล่านี้อาจเกิดจากปัญหาปกติ เช่น traffic เพิ่มหรือระบบมี bug ได้เช่นกัน ต้องตรวจหลักฐานก่อนสรุป

## แนวทางป้องกัน
1. ใช้ CDN หรือผู้ให้บริการป้องกัน DDoS
2. ตั้ง rate limit ตามลักษณะการใช้งานจริง
3. ใช้ WAF และกฎกรองทราฟฟิกที่ผ่านการทดสอบ
4. แยกบริการสำคัญและจำกัดทรัพยากร
5. ทำ monitoring และ alert สำหรับ traffic, latency และ error rate
6. เตรียมช่องทางติดต่อผู้ให้บริการและแผน incident response
7. ทดสอบความพร้อมด้วยการทดสอบโหลดที่ได้รับอนุญาตและมีขอบเขตชัดเจนเท่านั้น

## เมื่อเกิดเหตุ
- ติดต่อทีมระบบหรือผู้ให้บริการ CDN/Hosting
- บันทึกเวลา กราฟ และอาการที่พบ
- ปฏิบัติตามแผนรับมือที่ได้รับอนุมัติ
- สื่อสารกับผู้ใช้โดยไม่เปิดเผยข้อมูลภายใน
- หลังเหตุการณ์ให้ทบทวน capacity, configuration และ alert

## อย่าทำ
อย่าส่งทราฟฟิกจำนวนมากไปยังเว็บหรือ IP ของผู้อื่น อย่าทดสอบกับระบบจริงที่ไม่ได้รับอนุญาต และอย่าตอบโต้ด้วยการโจมตีกลับ
